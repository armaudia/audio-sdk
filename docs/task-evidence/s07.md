# S07 — native packaging and CI

Status: partial. macOS candidate packaging and local install verification are
implemented. Two clean macOS arm64 Release builds now produce identical
per-file manifests and byte-identical normalized archives. Linux x86-64,
hosted CI execution and Linux sanitizer qualification remain unverified.

The local packaging command is:

```sh
./scripts/package.sh build/all build/candidate
```

It installs into `build/candidate/audio-sdk-0.1.0`, normalizes the Darwin
static archive, compiles/runs C11 and C++20 consumers, runs both installed
conformance cases, creates a normalized tar.gz, and writes per-file and archive
SHA-256 manifests. Current local archive digest:
`82bb8f64c882b77a51e708bac0c79eae586c07cb0e96c84c8a9388d2100a387e`.
Candidate build identity:
`audio-sdk/0.1.0+sha256:fe66742bc610c4a1d27439c127908d803bc14555c6009a98d3339d594dc8d800`.
Installed provider reports are
`build/candidate/verification/{speex,highpass}-report.json`.

Two separate Release build directories (`build/repro-a` and `build/repro-b`)
were packaged independently. Their complete per-file manifests matched and
both archive hashes were
`82bb8f64c882b77a51e708bac0c79eae586c07cb0e96c84c8a9388d2100a387e`.
`scripts/package.sh` applies the archive normalizer to the installed static
library, so the result does not depend on a build-system post-link hook.
