# SDK-ZERO-FILL-PLC — deterministic synthetic zero-fill evidence

Task-local, **proposal-only**, **incomplete** and **not qualified** evidence for
a deterministic zero-fill packet-loss-concealment (PLC) baseline. The
candidate is modelled in Python at the public audio-sdk v0 boundary. It is
**synthetic, optional, unregistered and OFF by default**. It changes no
installed SDK behavior, public API/ABI, descriptor registry, registry default,
`CONTRACTS.md`, top-level `CMakeLists.txt`, board, handoff, other worktree or
branch. The installed v0 geometry is untouched: **16 kHz, mono, float32,
160 samples per call**.

## Boundary model and algorithm

The shipped public v0 facade has no frame-level "packet lost" input flag:
`as_frame_v0.flags` only admits `AS_FRAME_FINAL_INPUT`, and
`AS_RESULT_CONCEALMENT = 4` is a *result* flag. This fixture therefore models
the **host delivery-adapter boundary**: one call per 160-sample source frame,
a missing packet as `present=False, valid_count=0`, and concealed output slots
carrying flag `4` with `valid_count = 0`. Per `CONTRACTS.md`, adapter
concealment is **not a produced provider frame and cannot satisfy sample
conservation**; valid content is conserved by the good frames alone.

Zero fill is the simplest deterministic baseline: every concealed slot is
`0.0` for all 160 samples, with no context, weights, prediction, lookahead or
intrinsic algorithmic delay. Two explicit controls are run on the identical
erasure mask:

- **hold** (`hold_control`): repeat the last received good sample across the
  lost interval (zero-valued fallback before any good sample or at drain);
- **linear** (`linear_control`): ramp from the last good sample to the first
  sample of the next good frame, with explicit hold fallback at stream edges.

The 800-sample (5-frame) output buffer is an explicit host scheduling choice
that keeps source slots one-to-one with output frames; zero fill itself has
**0 intrinsic delay**. A 4-frame maximum burst and 8-call drain cap are
enforced. Frame admission rejects missing/short/wrong-shape/zero-length/
nonfinite/bad-padding frames, stale epochs, duplicates, out-of-order frames,
future packets, frames after final, and over-length bursts without changing
stream state. Reset, epoch, close and session isolation are exercised.

## Discrete validity, intervals, final partial window, state

Recorded under `decoded_intervals`, `availability`, `alignment`, `adverse`,
`final_partial_window` and `state` in `report.json`:

- One 160-sample output slot per source frame; concealed slots have flag `4`
  and zero valid samples and are excluded from the 37,280 valid content
  samples. Decoded duration is 2.5 s for every condition; first valid output
  at process-call index 5 (800-sample host buffer).
- Final partial window: 8 full frames plus 37 samples (1,317 samples). Frame 7
  is erased; the last frame is flagged final with `valid_count=37`, all 14
  produced frames are present, valid samples are bit-identical and the
  partial-window RMSE is `0.000000` in every condition. This is a synthetic
  boundary probe, not a real playout claim.
- Alignment: raw source origin `-800`, measured impulse peak index `4800`
  (expected `4800`), content lag `0`, all per-frame source mappings verified.
  Zero-fill intrinsic delay is `0`; the 800-sample value is host buffering.
- Missing frame, wrong shape, short frame, zero-length frame, nonfinite input,
  bad padding, stale epoch, future packet, duplicate, out-of-order packet and
  process after final are each rejected without changing stream state; a
  valid frame after rejection is accepted.
- A fifth consecutive erasure is rejected; a good frame after a four-frame
  burst is accepted. A leading erasure produces zero-valid concealment with
  explicit zero-fill/fallback counting (1 frame); two trailing erased frames
  are counted as fallback at drain; a boundary burst (frames 99–102) is fully
  concealed.
- Independent sessions are uncoupled; reset to a higher epoch is
  bit-identical to a fresh session, rejects stale frames, and processing after
  close is rejected. Bounded queue depth is 5 after each call and 0 after
  drain.
