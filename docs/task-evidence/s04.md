# S04 — sequential facade, lifecycle, bounded worker

Status: partial. Local Release, ASan/UBSan, and TSan checks pass; callback-safe
mode 1 remains unadvertised.

Evidence:

```sh
cmake --build build/all --parallel 2
ctest --test-dir build/all --output-on-failure
```

Result: 10/10 tests passed. The two conformance tests additionally checked
argument rejection, process metadata, validity intervals, 166 stream lengths
(empty, every final remainder 1–159, and 160/161/165/319/320/321), repeated
EOS, reset epoch/position, info/stats JSON, deterministic output hash and
buffered queue operation. The external provider fixture also passed its
delayed-identity case.

Mode 2 is synchronous and creates no worker. Mode 3 uses a worker and fixed
three-frame input/output queues. The built-ins advertise only modes 2 and 3;
mode 1 is rejected because callback instrumentation has not been performed.

`tests/test_queues.c` now parks the worker inside a provider callback using a
condition-variable barrier, fills the bounded input queue deterministically,
checks exact queue occupancy, rejects the next frame, then releases/drains and
checks source positions and valid counts. It does not depend on winning a
scheduler race. Worker backend failure now increments cancelled-interval
accounting for the failed in-flight input plus queued input/output frames
before clearing those queues.

Actual sanitizer commands, each in a separate build:

```sh
cmake -S . -B build/asan-ubsan -DCMAKE_BUILD_TYPE=Debug \
  -DAS_ENABLE_SANITIZERS=ON -DAS_BUILD_EXAMPLES=OFF
cmake --build build/asan-ubsan --parallel 2
ctest --test-dir build/asan-ubsan --output-on-failure
cmake -S . -B build/tsan -DCMAKE_BUILD_TYPE=Debug \
  -DAS_ENABLE_TSAN=ON -DAS_BUILD_EXAMPLES=OFF
cmake --build build/tsan --parallel 2
ctest --test-dir build/tsan --output-on-failure
```

Both sanitizer runs passed 10/10 on macOS arm64. Still open: queue operations
use `queue_mutex` and therefore the planned strict nonblocking guarantee is not
met; output-side saturation, exact cancelled sample intervals through reset
and close, failed reset, and 1,000-cycle concurrent reset/close stress are not
covered. No callback-safety claim is made.
