# S04 — sequential facade, lifecycle, bounded worker

Status: partial. Mode-3 submit/pull now use bounded SPSC rings with C11
release/acquire indices and do not take the queue mutex or signal the worker.
The worker polls its condition variable with a 1 ms timeout so callback-side
queue operations remain nonblocking. Mode 3 is rejected if callback-path
atomics are not lock-free. Callback-safe mode 1 remains unadvertised.

Evidence:

```sh
cmake --build build/all -j4
ctest --test-dir build/all --output-on-failure --timeout 45
```

Result: 10/10 passed. The two conformance tests additionally checked
argument rejection, process metadata, validity intervals, 166 stream lengths
(empty, every final remainder 1–159, and 160/161/165/319/320/321), repeated
EOS, reset epoch/position, info/stats JSON, deterministic output hash and
buffered queue operation. The external provider fixture also passed its
delayed-identity case.

Mode 2 is synchronous and creates no worker. Mode 3 uses a worker and fixed
three-frame input/output queues. The built-ins advertise only modes 2 and 3;
mode 1 is rejected because callback instrumentation has not been performed.

`tests/test_queues.c` parks the worker inside a provider callback using a
condition-variable barrier, fills the bounded input queue deterministically,
checks exact queue occupancy and rejection, then releases/drains. It also
verifies output high-water reaches the three-frame bound and performs 1,000
worker create/reset/close cycles. A reset with three accepted frames verifies
the exact cancelled valid-sample count (480) and interval count (3). Worker
failure counters now distinguish failed in-flight source samples from
cancelled queued input/output content. CTest bounds this test at 45 seconds.

Actual sanitizer commands, each in a separate build:

```sh
cmake --build build/asan-ubsan -j4
ctest --test-dir build/asan-ubsan --output-on-failure --timeout 60
cmake --build build/tsan -j4
ctest --test-dir build/tsan --output-on-failure --timeout 60
```

Release, ASan/UBSan, and TSan each passed 10/10 on macOS arm64. The 1,000 cycles are
sequential lifecycle cycles, not a concurrent reset/close overlap stress run.
Still open: exposing/validating every cancelled source range (rather than
counts) and all provider-buffered content, close cancellation reporting,
failed-reset coverage, and deterministic overlap coverage for submit/pull
against reset/close. No callback-safety claim is made.
