# SDK-NUMPY-SCIPY-SOUNDFILE-WAV-AND-RESAMPLING — offline WAV/resampling tooling fixture

Task-local, **proposal-only**, **incomplete** and **not qualified** Tool-profile
evidence. It is a deterministic, seeded synthetic fixture for the developer
adapter that mirrors `src/audioml_eval/audio.py`: FLOAT WAV write/read and
`scipy.signal.resample_poly` resampling. It is synthetic, optional,
unregistered, OFF by default, and changes nothing in the installed SDK: no
public API/ABI, descriptor, default, tolerance, build flag, board entry,
handoff or other worktree/branch. Installed v0 remains **16 kHz, mono,
float32, 160 samples per call**.

## Hard boundary: never SDK runtime timing

NumPy / SciPy / SoundFile `read`, `write` and `resample` here are **developer
fixtures and offline reference tooling only**. They are **NEVER included in
SDK runtime timing**. No SDK session, provider, callback, worker, device,
paced workload, deadline, CPU or memory result is collected or implied. The
only wall-clock artifact is `runtime-measurements.json`, an unpaced,
non-qualifying pointer with `qualification_status = blocked` and
`deadline_ns = null`. The tooling's conceptual ID
`tooling.numpy-scipy-soundfile-wav.v0` is recorded with `registered=false`,
`enabled_by_default=false`, `descriptor_settings={}`.

## Scope and exact public-boundary model

The fixture mirrors the exact semantics of the pinned
`src/audioml_eval/audio.py` boundary, including its guards:

- `read(path, rate=None, channels=None)`: reject Git LFS pointers by their
  first 40 bytes; `sf.read(..., dtype='float32', always_2d=True)`; reject
  unexpected rate, unexpected channel count and non-finite samples.
- `write(path, samples, rate)`: require a finite 2-D array and positive rate;
  `sf.write(..., format='WAV', subtype='FLOAT')`.
- `resample(samples, source_rate, target_rate)`: require 2-D finite-shape
  input and positive rates; reduce by `gcd`, use `resample_poly` with
  `window=('kaiser', 5.0)`, `padtype='constant'`, `cval=0`, cast to f32, and
  enforce `expected = ceil(len(samples) * up / down)`.
- `pcm16`, `sample_interval`, `prepare` (crop + resample) and `chunks` are
  mirrored with the same guards. The only intentional difference is **lazy
  optional imports**: a missing library is an explicit
  `missing_optional_selection` status instead of an import-time crash.

The tooling itself accepts 1/2/3 channels and 8 kHz–48 kHz rates for offline
preparation; the SDK runtime boundary stays 16 kHz/mono/f32/160. Nothing here
resamples audio inside a session — `resampling=none` remains the effective
v0 configuration.
