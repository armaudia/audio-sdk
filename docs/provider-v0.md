# Provider v0.1 implementation notes

The public C boundary is in `include/audio_sdk/provider_v0.h` and
`include/audio_sdk/session_v0.h`. The frozen source contract is
`CONTRACTS.md`, revision 0.1. The runtime accepts mono float32, 16 kHz, fixed
160-sample calls and one provider per session.

## Provider table and metadata

Each operation returns an `as_status_v0`. Provider state is created per
session, reset only on a quiesced control path, and destroyed after processing
has stopped. The SDK copies descriptor bytes, effective configuration, and
assets; providers must not retain caller pointers except for the lifetime of
the current operation. All process/drain output intervals are half-open sample
ranges and carry an epoch.

`buffering_delay_samples` is a measured integer alignment delay, not a
frequency-dependent phase description. The facade verifies output source
positions, counts, epoch, finite samples, and validity bounds. `callback_safe`
is false for both initial providers; only execution modes 2 and 3 are
advertised.

## Built-in provider IDs

| ID | Transform | Settings | Buffering delay |
|---|---|---|---:|
| `speex.ns.v0` | SpeexDSP preprocessing; internal PCM16 conversion | Denoise on, AGC/dereverb off, suppression −20 dB, VAD start/continue 35/20 | 160 samples |
| `dsp.highpass80.v0` | First-party second-order high-pass, double state | 80 Hz, Q 0.7071067811865476 | 0 samples |

Speex converts float to PCM16 with `lrint(clamp(x,-1,1)*32767)` under
`FE_TONEAREST`, then converts PCM16 to float by dividing by 32768. This is
quantized processing, not float-exact processing. Silence still traverses the
same processing path. The high-pass does not add clipping, a limiter, or VAD.

Effective configurations are generated by
`as_effective_config_create_v0`; callers should not hand-assemble canonical
JSON. Floats not in the restricted integer JSON subset are decimal strings in
provider configuration. The SDK validates the emitted bytes and the matching
descriptor digest before provider creation.

## External provider build

The installed package includes `share/audio-sdk/conformance`, including the
onboarding fixture. Build from the installed tree in a clean consumer directory;
no SDK source-tree path is needed:

```sh
SDK_PREFIX="/path/to/installed/audio-sdk-0.1.0"
CONSUMER_BUILD="$PWD/build/external-provider-consumer"
cmake -S "$SDK_PREFIX/share/audio-sdk/conformance/external_provider" \
  -B "$CONSUMER_BUILD" \
  -DCMAKE_PREFIX_PATH="$SDK_PREFIX" \
  -DAUDIO_SDK_CONFORMANCE_DIR="$SDK_PREFIX/share/audio-sdk/conformance"
cmake --build "$CONSUMER_BUILD" --parallel 2
ctest --test-dir "$CONSUMER_BUILD" --output-on-failure
```

The fixture covers delays 0, 1, 159, 160, 161, 256 (native hop 256), and 512 in
synchronous and buffered-worker modes. Fault-injection and unbounded-drain
variants are expected to be detected (their CTest entries use `WILL_FAIL`). It
is an onboarding template, not production DSP; see the installed
`conformance/external_provider/README.md`. It compiles against installed public
headers and conformance source, not the SDK's private `src/` tree.

This implementation is source-linked; the provider table is not promised as a
stable binary plugin ABI across SDK releases.
